# Visual CS brand style

**Version:** 1.0  
**Status:** Approved shared visual identity

Use this style across Visual CS work, including A-level and university computer science education, AI testing, and AI engineering topics. Keep the visual identity recognizable while choosing a composition that explains each subject clearly.

## Brand character

- Relaxed, trustworthy, curious, and professionally made.
- Help the audience understand a concept, follow a mechanism, and remember a clear takeaway.
- Use visual detail to explain relationships and state changes, not as decoration.

## Canvas and color

Use a light paper canvas for infographics and a deep navy canvas for video. Carry the same semantic colors and illustration language across both formats. On dark canvases, use warm ivory for primary text and adjust secondary lines and accents as needed for clear contrast.

| Role | Color reference | Use |
|---|---|---|
| Paper | Warm ivory `#F4EFE4` | Infographic canvas and light text on dark scenes |
| Ink | Deep blue-black `#183142` | Titles, body text, outlines, and video canvas |
| Slate | Muted blue `#5B7687` | Structures and secondary information |
| Teal | Dusty teal `#218F8A` | Inputs, active paths, and movement |
| Copper | Muted copper `#D68D45` | Values, outputs, and key results |
| Coral | Soft coral `#D96F62` | Warnings, exceptions, and control signals |
| Mist | Pale mist `#DFE7E5` | Quiet panels and secondary regions |

Treat the colors as shared visual references. Maintain strong text contrast, and pair color with labels, shape, or line style so meaning does not depend on color alone. Use the semantic role when it fits the explanation; do not force a color onto an unrelated concept.

## Illustration

- Use precise, vector-like diagrams and editorial technical illustration.
- Draw the objects and relationships needed to explain the topic.
- Use cutaways, layered diagrams, state snapshots, leader lines, and inset details when they clarify the mechanism.
- Use fine, consistent linework, restrained paper grain, and occasional hatching.
- Prefer clear silhouettes and readable labels over photorealistic hardware.

## Typography

- Use a large, expressive editorial serif for the main title.
- Give section headings a clear size and weight hierarchy.
- Keep explanatory labels legible at the intended display size.
- Use monospaced type for code, addresses, formulas, and sample data.
- Keep exact terminology and numbers away from footnote-sized text.

## Composition and information density

- Give each infographic one dominant diagram or illustration that explains its central claim.
- Add two to five useful supporting views, such as a worked example, comparison, boundary case, hierarchy, timeline, or misconception.
- Use an asymmetric editorial layout with a clear reading path, varied element sizes, and deliberate whitespace.
- Show relationships through placement, arrows, connectors, containers, and state changes.
- Make the page rich and orderly. Use meaningful explanatory detail rather than filler.
- Let the composition follow the topic. Do not force every work into the same layout.

## Format guidance

- **Infographics:** warm light canvas; portrait 4:5 by default. Change the ratio when the content or publishing destination calls for it.
- **Video:** deep navy canvas; reveal information over time and preserve the identity of recurring objects across scenes.
- **Other media:** keep the palette roles, typography hierarchy, line language, and illustration finish consistent with the same brand.

## Avoid

- Generic dashboard grids and rows of equal cards.
- Neon colors, purple gradients, glossy 3D hardware, or heavy background texture.
- Decorative icons without an explanatory role.
- Fake labels, invented numbers, unsupported diagrams, or tiny illegible copy.
- Copying another creator's work or signature composition.

Paste this block unchanged into infographic prompts. Add the audience, topic facts, exact copy, and composition after it. See [IMAGE_PROMPT_GUIDE.md](IMAGE_PROMPT_GUIDE.md).

```text
Create a polished editorial technical field guide in a relaxed, trustworthy,
professionally art-directed visual style. Use a warm ivory paper canvas, a quiet
low-saturation base, and the shared semantic palette: deep blue-black for type
and outlines, muted slate for structures, dusty teal for inputs and active paths,
muted copper for values and results, and soft coral for warnings or control
signals. Use precise vector-like diagrams, clean silhouettes, fine consistent
linework, restrained paper grain, and occasional fine hatching. Use an expressive
editorial serif for the main title, legible compact labels, and monospaced type
for code, addresses, and formulas. Build an asymmetric page around one dominant
annotated mechanism diagram, then add two to five topic-relevant supporting
details with a clear reading path. Make the page rich but orderly, with deliberate
whitespace. Keep colors, typography roles, line language, and surface treatment
recognizable across topics, while letting each topic have its own composition.
Do not use generic dashboard grids, equal-sized cards, decorative filler, neon,
purple gradients, fake technical labels, invented data, or tiny unreadable text.
```

## Maintaining the style

Use this file as the shared visual source of truth. Record topic-specific choices in that project's visual brief. Update this guide when the brand changes, then use the revised rules for new work.
